# AGENTS

## Frontend map
- `PhotoElectricEffect/zindex.html` and `FranckHertz/zindex.html` use shared Web Components in `static/js/components/` and `static/js/lib.js`; `DiffractionInterference/index.html` retains its own page layout.
- `static/css/app.css` and component Shadow DOM define the ReStylingFranckHertz visual baseline. Photoelectric intentionally does not load or ship `layout.css`; do not restore it to address sizing. Desktop `.video-row` uses bounded flex sizing to share space between high-resolution WHEP video and tool details; the shared CSS also affects Franck-Hertz.
- ReMLA supplies `remlaJsonSocket.js` and `reader.js` at website deployment. `static/js/remlaJsonApp.js` owns one JSON WebSocket per connected page and resolves `/ws` relative to the page directory (including explicit `index.html` URLs under a proxy mount); Photoelectric's `static/js/app.js` handles device-to-UI mapping, while Diffraction keeps its mapping in `static/js/main.js`. Components emit intent and receive state; they do not open WebSockets. Franck-Hertz is video-only: do not load the JSON control bridge there until device mappings, handoff, and ownership are implemented, as an idle owner disconnect can reset the lab.
- Queue and control updates render in the existing page headers (Web Component `header.js` or Diffraction's `#PageHead`). Potentiometer degrees use `degrees-per-step="1.8"` for integer motor steps; validate hardware mappings before changing this value.
- `video-component` uses the local MediaMTX WHEP reader for live video, independently of JSON command transport. The snapshot button is still a placeholder, not a high-resolution still capture. Fault lifecycle, command-error UI, and `power: "unknown"` after reset still need explicit user-facing handling; do not present these controls as production-ready.
- `diffrac{1,2}.yml` and `photo{1,2}.yml` now define named PDU-backed consumers and instrument power routes; every routed device shares its provider's PDU lock. Keep each lab's existing outlet map: diffrac1 uses Laser/Screen outlets 1/2, diffrac2 5/6; photo1 uses Electrometer/Multimeter/HgNeLamp/Ambient outlets 5/6/7/8, photo2 1/2/3/4. Diffraction camera buttons call `cameraName` (`view`, `ruler`, `screen`) so server config owns slot mapping, but physical view/ruler mapping still needs operator validation.
- Photoelectric instrument SVG Power hotspots use `power_toggle` through configured PDU routes; other instrument keys remain `press/SYST:KEY ...`. Do not map Power back to `press/POWER`. Test the component dispatch with `tests.test_photoelectric_json_frontend` and only validate outlet cycling under operator supervision.
- Keep Photoelectric and Franck-Hertz asset URLs page-relative (`static/...`) under proxy mounts. Do not load legacy and JSON socket clients on one page.

## Validation and safety
- Run `python -m unittest discover -s tests` for frontend and config checks, or `python -m unittest discover -s tests -p 'test_lab_config_json_compat.py'` for focused hardware-free config guards. Firefox browser cases include a wide-video layout regression; they skip when the browser is unavailable. ReMLA's YAML/config validation also needs its existing Python environment; never initialize hardware from a frontend test.
- Related source YAML uses `${secret:asdipdu-password}` and `${secret:pepdu-password}` references; no secret files, installed lab configuration, or backend service were modified for the photo1 website test. Other lab YAML may still contain literal credentials. Never copy, print, or expose credential values; operator must provision root-owned secret files, rotate exposed values, verify actual hardware mappings, and review missing website/network settings and the intentionally unchanged legacy diffrac2 PDU mode before deploying any candidate YAML.
- Keep local source branches separate; do not merge the JSON-testing branch wholesale, publish, or deploy without operator approval.
- Photo1's frontend-only test site is assembled independently of the installed lab workspace and served by nginx on local port 8080. The service/YAML stay on the installed release; `sudo remla setup deploy-website` would recopy unchanged workspace files and overwrite the test site. Coordinate before redeploying and preserve the site/CSS/SVG rollback copies listed in `roadmap.md` until operator acceptance.
