# remoteLabs frontend

- `PhotoElectricEffect/zindex.html` and `DiffractionInterference/index.html` use `static/js/remlaJsonApp.js` for one JSON WebSocket per page; ReMLA supplies `static/js/remlaJsonSocket.js` and `static/js/reader.js` when deploying a website. `PhotoElectricEffect/static/js/app.js` handles owner/queue/handoff, UI-state follow and owner-only private snapshot downloads. The shared `static/js/components/video.js` plays MediaMTX WHEP; snapshot tickets belong in the Bearer header, never the URL or logs.
- `FranckHertz/zindex.html` is **video-only**; its original `index.html` is separate. Do not connect control before validating hardware mappings and owner handoff. Shared `static/css/app.css` and components affect all pages; retain the restyled layout without `layout.css` on Photoelectric.
- `photo{1,2}.yml` and `diffrac{1,2}.yml` in this branch are the unchanged `justLabs` baseline, **not** the review-only power-route/secret candidate. Power commands (`power_*`) are blocked by default in the JSON adapter and component handlers. Only add `data-routed-power` to the page body after an operator approves and installs the matching named consumers, routed instruments, shared locks, secrets and physical outlet mappings. This browser marker is an operational safeguard, not a backend security boundary. Diffraction's legacy `Ambient` on/off command is separate. Never commit credentials or copy proposed YAML to a Pi.
- The Photoelectric snapshot button needs a compatible ReMLA runtime and separately provisioned root snapshot broker/recovery, plus explicit selected-lab `stillCapture`; a normal ReMLA install alone does not enable it. `sudo remla setup deploy-website` can overwrite the independent photo1 test site; plan backups first. Owner disconnect/refresh can reset or move hardware.
- Run `python -m unittest discover -s tests` for all browser/frontend checks (Firefox cases skip without Firefox). Use `python -m unittest tests.test_photoelectric_json_frontend` for focused regressions; do not run device commands or deploy during these tests. Review `roadmap.md` before merging or rolling out.
