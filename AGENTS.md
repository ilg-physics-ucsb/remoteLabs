# AGENTS

## Frontend map
- `PhotoElectricEffect/zindex.html` and `FranckHertz/zindex.html` use shared Web Components in `static/js/components/` and `static/js/lib.js`; `DiffractionInterference/index.html` retains its own page layout.
- `static/css/app.css` and component Shadow DOM define the ReStylingFranckHertz visual baseline. Photoelectric intentionally does not load or ship `layout.css`. Desktop `.video-row` bounds video beside the tools. `tool-detail-component` bounds slotted panels; SVG maps, toggle images, and the knob arrow/image row fit proportionally using named CSS size containers, while the knob's selector stays legible. At landscape tablet viewports (at least 1024px wide and 650px of browser content height), CSS reserves a 360px-wide/340px-tall detail, `resizer.js` limits video growth, descriptions alone scroll, and controls/instructions fit without scrolling. Smaller or portrait layouts retain the earlier scroll fallback pending a separate mobile redesign. Shared rules affect Franck-Hertz too. The tablet control scaling is live on photo1 for operator testing; source is tracked on the feature branch.
- ReMLA supplies `remlaJsonSocket.js` and `reader.js` at website deployment. `static/js/remlaJsonApp.js` owns one JSON WebSocket per connected page and resolves `/ws` relative to the page directory (including explicit `index.html` URLs under a proxy mount); Photoelectric's `static/js/app.js` handles device-to-UI mapping, while Diffraction keeps its mapping in `static/js/main.js`. Components emit intent and receive state; they do not open WebSockets. Franck-Hertz **`zindex.html` only** is video-only: its separate legacy `index.html` still loads a control socket. Do not load the JSON bridge in `zindex.html` until device mappings, handoff, and ownership are implemented; even an idle owner disconnect can reset the lab.
- `static/js/components/alert-dialog.js` is wired into Photoelectric's `zindex.html`: the JSON bridge forwards server `alert` event data (`severity`, `title`, `message`) via `remla:alert`, buffering up to ten early messages. Routine queue position stays in the header; `app.js` adds one informational queued-visitor notice on joining. Photoelectric control widgets (including header Ambient) are greyed, inert, and command-gated unless `ownership.control` grants control in `ready`; navigation, manuals, video, and descriptions remain available. Its handoff Yes/No API is separate: Yes sends `Experiment/handoff {choice: "reset"}`, No sends `continue`, and disconnect/expired handoff sends nothing. The backend has no generic answerable-alert reply protocol; Diffraction retains its separate modals/native handoff confirm. Queue notice/control gating is live on photo1 for operator testing; source is tracked on the feature branch.
- Queue and control updates render in the existing page headers (Web Component `header.js` or Diffraction's `#PageHead`). Potentiometer degrees use `degrees-per-step="1.8"` for integer motor steps; validate hardware mappings before changing this value.
- `video-component` uses the local MediaMTX WHEP reader for live video, independently of JSON command transport. The snapshot button is still a placeholder, not a high-resolution still capture. Fault lifecycle, command-error UI, and `power: "unknown"` after reset still need explicit user-facing handling; do not present these controls as production-ready.
- `diffrac{1,2}.yml` and `photo{1,2}.yml` define named PDU-backed consumers and instrument power routes; every routed device shares its provider's PDU lock. Keep each lab's existing outlet map: diffrac1 uses Laser/Screen outlets 1/2, diffrac2 5/6; photo1 uses Electrometer/Multimeter/HgNeLamp/Ambient outlets 5/6/7/8, photo2 1/2/3/4. Photo1's two wheels have **different** locks (`colorwheel` and `densityWheel`); its installed 0.4.6 backend can dispatch their JSON commands concurrently. Diffraction camera buttons call `cameraName` (`view`, `ruler`, `screen`) so server config owns slot mapping, but physical view/ruler mapping still needs operator validation.
- Photoelectric instrument SVG Power hotspots use `power_toggle` through configured PDU routes; other instrument keys remain `press/SYST:KEY ...`. Do not map Power back to `press/POWER`. Test the component dispatch with `tests.test_photoelectric_json_frontend` and only validate outlet cycling under operator supervision.
- Keep Photoelectric and Franck-Hertz asset URLs page-relative (`static/...`) under proxy mounts. Do not load legacy and JSON socket clients on one page.

## Validation and safety
- Run `python -m unittest discover -s tests` for frontend and config checks, or `python -m unittest tests.test_photoelectric_json_frontend` for focused browser-backed alerts/handoff/layout regressions; Firefox cases skip when the browser is unavailable. ReMLA's YAML/config validation also needs its existing Python environment; never initialize hardware from a frontend test.
- Related source YAML uses `${secret:asdipdu-password}` and `${secret:pepdu-password}` references; no secret files, installed lab configuration, or backend service were modified for the photo1 website test. Other lab YAML may still contain literal credentials. Never copy, print, or expose credential values; operator must provision root-owned secret files, rotate exposed values, verify actual hardware mappings, and review missing website/network settings and the intentionally unchanged legacy diffrac2 PDU mode before deploying any candidate YAML.
- Keep local source branches separate; do not merge the JSON-testing branch wholesale, publish, or deploy without operator approval.
- Photo1's frontend-only test site is assembled independently of the installed lab workspace: `PhotoElectricEffect/zindex.html` becomes `/var/www/remla/index.html`, shared `static/` assets sit alongside it, and nginx serves the site on local port 8080. The latest queue UI switch changed only HTML, Photoelectric `static/js/app.js`, shared `static/css/app.css`, `static/js/components/header.js`, and `static/js/components/alert-dialog.js`; exact previous live copies are at `/var/www/.remla-photo1-queue-before-e05071e2ec32/`. Earlier alert, tablet, and generic backups are recorded in `roadmap.md`. The installed backend remains the isolated 0.4.6 motor-limit test runtime, with `/opt/remla/previous` pointing to earlier 0.4.6; lab YAML was unchanged. `sudo remla setup deploy-website` would overwrite the independent test site. Coordinate before redeploying and preserve rollback copies until operator acceptance.
